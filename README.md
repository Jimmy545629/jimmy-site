# jimmy-site

Jimmy 的个人网站 —— 一个从零开始、边学边做的项目。

## 这个网站要做成什么

> **「来源看板」**
> 我只盯 3–5 个固定来源（几个网站、博客或账号），去看过之后，把自己发现的东西贴进来。
> 网站按来源归好、排成一条时间线，并告诉我「哪个来源我已经好久没去看了」。
> 数据存在我自己的项目里，不在别人的服务器上。

⚠️ 产品方向在 **Day 3** 换过一次（原来是「极简打卡网页」）。
换的原因、对比过的三条路线、以及「本期不做」的完整清单，都在 `research.md` 里。

## 怎么运行

**双击 `index.html`**，用默认浏览器打开，就是完整的网站。

- 不需要装任何东西（Node、Python、数据库、包管理器 —— 一个都不用）
- 不需要敲任何命令，**也不需要起本地服务**
- **拔掉网线也能用**：整个网站不引用任何在线资源（CSS、JS、字体、图标全部在本地）

> **为什么不走 `localhost`**：这是一个「双击就能用」的纯静态网页，理由写在 `TECH_DESIGN.md` 第 3.1 节。
> Day 7 交作业时另截了一张 `http://localhost:8010/index.html` 的图（清单要求地址栏里要有 localhost），
> 那是临时起了一个本地小服务、专门为了截图用，**网站本身不需要它**。

## 怎么用（打开之后做这三件事）

1. **加来源**：点右上角「添加来源」，把你要盯的地方填进去（名称必填、地址可选）。**最多 5 个**，加第 6 个会被拦住。
2. **记一条**：去看过某个来源之后，点那张卡片上的「记录一条」，填标题（必填）、链接和「我的一句话」（都可以不填）。
   记录时间默认今天，**补记前几天看到的东西时可以改成那天**。
3. **看提示**：页面顶部会自动写「你现在最该看的是：XXX（N 天没记录了）」；
   对应的卡片上会**同时**出现红色标记和「**该看了**」两个字。去补记一条，标记就消失。

**每个星期点一次右上角「导出数据」**：会在「下载」文件夹里生成一个 `sourceboard-日期.json`。
那个文件就是全部数据，拷到 U 盘或别的文件夹都是完整一份；
换电脑、换浏览器、或者浏览器数据被清掉时，用「导入数据」把它读回来（**导入前会自动先备份一份当前数据**）。

> ⚠️ 数据存在**这个浏览器的这个来源**下，所以：
> 双击 `file://` 打开、和从 `http://localhost` 打开，是**两份互不相通的数据**。平时固定用一种打开方式就好。
> 另一个知道的代价：清理浏览器数据会丢，所以「导出」出来的那个文件才是保命的备份。

## 文件结构

```
jimmy-site/
├── index.html             首页：顶部提示条 + 我盯的来源 + 时间线
├── source.html            某个来源的详情页（地址形如 source.html?id=来源id）
├── assets/
│   ├── config.js          所有常量：7 天阈值 / 5 个上限 / 存储键名 / 格式版本
│   ├── store.js           数据的唯一出入口（读、写、导出、导入）
│   ├── rules.js           只做计算：X 天前、该看哪个来源、排序
│   ├── ui.js              画页面、收输入、弹窗（两个页面共用）
│   └── style.css          全部样式
├── research.md  PRD.md  TECH_DESIGN.md  AGENTS.md
└── README.md
```

一句话记住分工：**界面只负责「画」和「收集输入」，算数交给 `rules.js`，存取交给 `store.js`。**

## 关于 .env

`.env` 是存放数据库密码、密钥这类敏感信息的本地文件。
它已经被 `.gitignore` 忽略，永远不会出现在 GitHub 上。

需要新增配置项时，先写进 `.env.example`（这个是要上传的模板），
再在自己的 `.env` 里填上真实的值。
