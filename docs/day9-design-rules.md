# Day 9 · 前端设计规则（可逐条检查的「尺子」）

> 目的：把「像不像一个正经产品」这种**感觉**，翻译成**能算出来、能量出来**的硬指标。
> 每一页都要能通过下面 7 条，通不过就是问题——不靠审美争论。
>
> 建立日期：2026-09-26（Day 9）
> 适用文件：`index.html`、`source.html`、`assets/style.css`

---

## 为什么要做这件事

「看起来不太专业」是模糊的抱怨，改不动。但把它拆开，会发现绝大多数「不专业」
其实是少数几个可测量的问题反复出现：

- 灰字太浅，**对比度算出来只有 2.6:1**（标准是 4.5:1）→ 读起来累
- 间距随手写（14、18、22、28…），**没有刻度** → 节奏乱
- 同一个页面出现**三条不同的左对齐线** → 视线找不到支点
- 字号有 16 种（11.5、12、12.5、13、13.5…）→ 层级没了，只有"密密麻麻"

只要这几条修掉，观感会立刻变。所以先定规则，再拿规则去量。

---

## 规则 1：文字对比度 ≥ 4.5 : 1

- **标准**：普通文字（小于 24px）前景色与背景色的对比度 **≥ 4.5:1**；
  大字号（≥ 24px，或 ≥ 18.66px 且加粗）可以放宽到 **≥ 3:1**。
  这是 WCAG AA 级，也是「灰字看得清」的最低线。
- **为什么**：低于这个值的浅灰字，在明亮环境、老显示器、或者在 175% 缩放
  的屏幕上会糊成一片——不是"高级的克制"，是"没做完"。
- **怎么量**：把前景色和背景色换算成相对亮度，用
  `(亮的 + 0.05) / (暗的 + 0.05)` 算比值。半透明要先把颜色叠加到底色上再算。
- **判定**：**任何一条正文文字低于 4.5:1 就是不合格**，必须改深。
  只有纯装饰性的分隔线、图标不受这条约束。

## 规则 2：间距走 8px 刻度

- **标准**：`margin` / `padding` / `gap` 的值 **只允许 4 的倍数**（4、8、12、16、24、32、48）。
  并且同一类元素之间的间距**必须相等**。
- **为什么**：人眼对"节奏"很敏感。14px 和 16px 混着用，说不清哪里怪，但就是乱。
  统一到刻度上，页面会自己整齐起来。
- **怎么量**：把页面上所有元素的四边 `margin` / `padding` 和 `gap` 收集起来，
  找出**不是 4 的倍数**的值，逐个报告它属于哪个选择器。
- **判定**：出现 14、18、22、26 这类值就是不合格。

## 规则 3：一条左对齐轴线

- **标准**：同一个页面里，所有**正文块的左边缘**应当对齐在**同一条竖线**上。
  允许例外只有：有缩进关系的嵌套内容（例如卡片内部的次级文案），
  且缩进量必须一致（建议正好 16 或 24px）。
- **为什么**：左边缘是视线扫读的支点。标题在 0、卡片文字在 22、页脚在 2——
  三条线一起出现，页面就"散"了。
- **怎么量**：取页面标题、面板内首个文字、卡片内首个文字、页脚首个文字，
  读出它们各自的 `getBoundingClientRect().left`，看是几个不同的值。
- **判定**：同层级的正文块出现 ≥2 条不同的左边缘 = 不合格。

## 规则 4：字号阶梯收敛到 5 档以内

- **标准**：全站字号**不超过 5 个档位**，相邻档位差 **≥ 2px**。
  推荐阶梯：`12 / 14 / 16 / 20 / 24`。
- **为什么**：字号是层级信号。11.5 / 12 / 12.5 / 13 / 13.5 这种"半步"，
  视觉上分不出来，却让代码里出现了 8 个"层级"——等于没有层级。
- **怎么量**：收集页面上所有不同的 `font-size` 值，按降序列出并统计各自用了多少次。
- **判定**：档位 > 5，或存在差值 < 2px 的相邻档位 = 不合格。

## 规则 5：键盘焦点必须看得见

- **标准**：所有可点击元素（按钮、链接、卡片上的操作）在用 `Tab` 键聚焦时，
  必须有**明显的视觉变化**（描边圈或背景变化），且这个变化不能只靠颜色深浅。
  同时点击目标尺寸建议 ≥ 32×32px（触屏 ≥ 44×44px）。
- **为什么**：不用鼠标的人完全靠焦点圈判断"我现在在哪个按钮上"。
  焦点圈缺失 = 这个网站对键盘用户不可用。
- **怎么量**：用调试接口发 `Tab` 按键，读 `document.activeElement`，
  再读它 `getComputedStyle` 的 `outline-width` / `outline-style` / `box-shadow`，
  看有没有可见变化。
- **判定**：`outline: none` 且没有替代的 `box-shadow` = 不合格。

## 规则 6：状态不能只靠颜色区分

- **标准**：任何"状态"（禁用、过期、选中、错误）在视觉上至少要有**两重信号**，
  例如"颜色 + 文字"、"颜色 + 形状"、"颜色 + 图标"。
- **为什么**：约 8% 的男性有红绿色觉差异。只靠颜色传递的信息，对他们等于没传递。
  另外这条也逼我们把话说清楚——比如按钮为什么不能点，应该直接写出来。
- **怎么量**：找出所有用了 `opacity` 变淡、或只换了颜色的状态样式，
  检查有没有配套的文字或图形变化。
- **判定**：只改颜色/透明度、没有任何文字或形状提示 = 不合格。

## 规则 7：一屏只有一个「主角」

- **标准**：同一屏内，最大字号与第二档字号的比例 **≥ 1.4 倍**；
  正文最小字号 **不低于 12px**；次要说明文字不低于 12px 且对比度达标。
- **为什么**：产品页面要让人一眼知道"看哪里"。所有字号都挤在 13–16 之间时，
  眼睛没有落点，就只能靠"一张张贴着读"。
- **怎么量**：取最大字号与次大字号求比值；取最小字号。
- **判定**：比值 < 1.4，或存在 < 12px 的文字 = 不合格。

# 审查结果（2026-09-26 实测）

不是"看着差不多"，是拿脚本在真浏览器里量出来的数字。
量尺脚本：`.tmp/scripts/audit.mjs`（无头 Edge + 调试接口，读 `getComputedStyle`）
样本：空状态 + 有数据状态（5 个来源 / 12 条记录），桌面 1000px 与手机 375px。

| 规则 | 修前实测 | 修后实测 | 结论 |
|---|---|---|---|
| 1 文字对比度 | **49 处不合格**，最低 1.87:1 | **0 处不合格** | ✅ |
| 2 间距刻度 | **17 处**不在 4 的倍数上（14/18/22/7/9/10…） | **0 处** | ✅ |
| 3 左对齐轴线 | 5 条线：50 / 73 / 90 / 75 / 52 | 3 条线：**50 / 75 / 92**（互为 ±1px 边框） | ✅ |
| 4 字号阶梯 | **8 档**：24/16/15/14/13.5/13/12.5/12 | **4 档**：24 / 16 / 14 / 12 | ✅ |
| 5 焦点 + 点击区 | 焦点圈是浏览器默认 `1px auto`；控件最小 24×24 | 统一 `2px solid` 品牌色；控件最小 **32×32**（0/39 个不达标） | ✅ |
| 6 状态表达 | 禁用态只有 `opacity: .45`（白字蓝底 1.87:1） | 实心→描边**形状变化** + 灰字（5.28:1） | ✅ |
| 7 主角唯一 | 24 ÷ 16 = 1.5 | 24 ÷ 16 = 1.5，最小字号 12px | ✅ |

手机 375px：**无横向溢出**（scrollWidth = clientWidth = 375）。
控制台：**0 条报错、0 个未捕获异常**。
真机功能验证 29/29 通过（空状态加来源、记录一条、刷新后数据还在、mock 数据 5 卡 12 条）。

## 今天修的 6 处，按"对『像不像正经产品』的影响"排序

1. **次要文字的灰色（规则 1）** —— 影响最大的一处。
   原来 `#98a1af` 在白底上只有 **2.61:1**、在页底上 **2.47:1**，
   比标准低了一半。「最后记录：」「3 天前」「编辑 / 删除」、页脚、空状态文案
   全都用的这个色 —— 等于整页的"说明性文字"集体发虚。
   改成 `#667085`（白底 4.97:1 / 页底 4.72:1）。这一处一动，49 处不合格里的大半直接消失。
2. **禁用态的表达（规则 6）** —— 原来"不能点"完全靠变淡，
   白字压在变淡的蓝底上只有 **1.87:1**，是全场最低。
   改成"实心填充 → 浅灰底 + 描边"，按钮**形状**变了，字也看得清。
3. **字号从 8 档收到 4 档（规则 4）** —— 13 与 13.5、15 与 16 差不到 1px，
   肉眼看不出却让"层级"失效。收敛后 24 ÷ 16 = 1.5，标题才真的像标题。
4. **间距上刻度（规则 2）** —— 14/18/22/7/9/10 混着用是"节奏乱"的根源。
5. **左对齐轴线（规则 3）** —— 面板内边距 22 → 24、页脚那 2px 归零，
   轴线从 5 条收到 3 条（页面 50 / 面板 75 / 卡片 92，正好各差 25px）。
6. **点击区与焦点圈（规则 5）** —— 时间线的「编辑 / 删除」看着像文字，
   但它是真按钮，命中区原来只有 24×24（等于两个字那么宽），手机上容易点空。

# 余力加练：把规则写成「可复用组件约束」

规则写在文档里，下一个页面照样会写错。所以这一步做的是：
**把规则从"文档里的句子"变成"改一处、全站生效的变量"**，放在 `assets/style.css` 顶部。

| 变量 | 对应规则 | 作用 |
|---|---|---|
| `--sp-1` … `--sp-7`（4/8/12/16/20/24/32） | 规则 2 | 间距只能从这 7 个里挑，写不出 14、22 这种数 |
| `--fs-1` … `--fs-4`（24/16/14/12） | 规则 4 | 字号只有 4 档，加第 5 档必须显式改这里 |
| `--ink` / `--ink-soft` / `--ink-faint` | 规则 1 | 三个层级的文字色，**每个后面都写了实测对比度** |
| `--disabled-bg` / `--disabled-ink` / `--disabled-line` | 规则 6 | 禁用态整套配色，换主题只改这三个 |
| `--focus-ring` | 规则 5 | 焦点圈颜色，全站共用一条 |
| `--pad-panel: 24px` / `--pad-card: 16px` | 规则 3 | 两级缩进量，轴线就是由它俩算出来的 |

这样做的好处很具体：**下次要调，改一个变量就够了**，
不用再像今天这样在 900 行 CSS 里找散落的 14px / 22px。
`rules.js` 里的 `TAG_COLORS` 也是同一个思路——一组颜色集中在一行，
今天只把不过线的那一个（`#0f8a6a` → `#0b7a5e`）加深，其余四个一个没动。
