## 一、为什么要抽：同一个结构，手抄了四五遍

抽之前，页面上这些结构全都是在 `ui.js` 里一段一段手写出来的：

| 结构 | 手写了几遍 | 在哪 |
|---|---|---|
| 弹窗里的「标签 + 控件 + 提示」 | **4 遍** | 添加来源 / 记录一条 / 编辑记录 / 重命名来源 |
| 弹窗底部的「取消 + 确定」按钮行 | **4 遍** | 同上 |
| 来源卡片 | 1 遍 | 首页 |
| 时间线里的一条 | 1 遍 | 首页 + 详情页（共用） |
| 来源标签（小色块） | 1 遍 | 时间线 |
| 按钮 | 散落 8 处 | 各处 |

**手抄的代价**不是"多打几个字"，而是**改的时候会漏掉一处**。
漏掉的那处就成了「跟别人长得不一样」的异类——而且它不会报错，只会静静地不一致。

## 二、抽出来的是什么：7 个积木

新文件 `assets/components.js`，对外叫 `window.SBComponents`：

| 积木 | 管什么 | 谁来用 |
|---|---|---|
| `h(tag, props, 子节点…)` | 最底层的建元素工具。**唯一的文字入口是 `textContent`** | 内部 + ui.js |
| `Card({…})` | 一张来源卡片 | 首页 |
| `Row({…})` | 时间线里的一条记录 | 首页 + 详情页 |
| `Field({…})` | 弹窗里的一个输入项 | 4 个弹窗 |
| `ModalFoot({…})` | 弹窗底部的按钮行 | 4 个弹窗 |
| `Button({…})` | 所有能点的按钮（含伪装成文字的、筛选用的小胶囊） | 各处 |
| `Tag(text, color)` | 来源标签那个小色块 | 时间线 |

抽完之后 `ui.js` 的角色变了：**它只决定「摆哪些积木、每块里放什么内容」，
不再决定「每块积木长什么样」。**

## 三、最要紧的一步：把视觉规则变成「积木自己就遵守的约束」

Day 9 那次把规则变成了 `style.css` 里的变量（`--sp-*` / `--fs-*` / `--ink-*`）。
这次又往前推了一步——**把规则写进积木本身**，让某些错误在结构上就犯不出来：

| 规则 | 以前的写法 | 现在的约束 |
|---|---|---|
| **规则 6** 状态不能只靠颜色 | 手写：加 `is-stale` 类，**然后记得**再补一个「该看了」标签。两件事分开做，容易只做一半 | `Card({ stale: true })` —— 组件**同时**加类别和标签文字。想漏也漏不掉 |
| **规则 1** 标签白字要有 4.5:1 | 手写：从 `TAG_COLORS` 里取一个颜色塞进去。如果哪天有人手写个别的色，没人拦 | `Tag(text, color)`——**只接受白名单里的颜色**，传了名单外的会被挡下、退回安全色并在控制台说一声 |
| **规则 5** 键盘要走得到 | 手写：`document.createElement('button')` + 记得设 `type`。忘了就变成表单里的"提交"按钮 | `Button()` 一律造 `<button type="button">` |
| **规则 2/4** 间距和字号 | 写在 CSS 里 | `SBComponents.RULES` 把这些数值**声明出来**，测试脚本读同一份来核对（防止有人绕过组件手写个 13px） |

另外还有一个**声明的约束表** `SBComponents.RULES`：

```
spacingScale: 4                  间距刻度
fontSizeScale: [12, 14, 16, 24]  只准这 4 档字号
minTarget: 32                    可点元素最小 32×32
contrastNormal: 4.5 / contrastLarge: 3
```

## 四、怎么证明「没改坏」——不是看代码，是在浏览器里量

昨天能用的东西，今天重构了一遍，**必须重新证明它还能用**（`AGENTS.md` 第 3 条）。

| 验证 | 脚本 | 结果 |
|---|---|---|
| **功能没坏**：空状态 → 添加来源 → 记录一条 → 刷新后数据还在 → mock 数据 5 卡 12 条 | `verify-day9.mjs`（Day 9 那套） | **29 / 29 通过** |
| **组件真的在管事**：逐层核对直接子元素的 class 序列、约束是否生效、声明与实际是否一致 | `verify-components.mjs`（本次新写） | **37 / 37 通过** |
| **视觉没退步**：对比度 / 间距 / 字号 / 轴线 / 控件尺寸 / 手机溢出 | `audit.mjs` | 全部与修复后**完全一致**（对比度 0 处不合格、字号 4 档、间距 0 处离刻度、轴线 50/75/92） |

几条比较有意思的证据：

- **「规则 6」的约束真的生效**：页面上 2 张陈旧卡片，缺「该看了」文字的 **0 张**；
  反过来「有该看了文字但不是陈旧态」的也是 **0 张** —— 两个方向都对得上。
- **两个页面共用同一套**：详情页和首页渲染出来的记录结构指纹**逐字节相同**：
  `["div|item-head","a|item-title","p|item-note","div|item-acts"]`。
- **声明和实际没有对不上**：组件声明字号只有 12/14/16/24，页面实际用到的就**正好是这 4 档**；
  声明间距是 4 的倍数，实际 **0 处**离刻度（自动跳过 5 处 `margin: auto` 居中——那是居中算出来的像素，不是作者写的）。
- **弹窗**：`.field` 用的是 `<label>` 而不是 `<div>` —— 这条有实际意义：点标签就能聚焦到输入框。
- **0 条 console 报错、0 个未捕获异常、0 条「标签色不在白名单」告警**。

## 五、以后要加一块新「积木」，怎么做

1. 在 `components.js` 里加一个函数，返回 DOM 元素；
2. **只用 `h()` 造元素**，不要拼 `innerHTML`（AGENTS.md 第 4 条第 5 项）；
3. **不写颜色/间距/字号的字面值**——这些都归 `style.css`；
4. 如果这块积木涉及「状态」「可点」「颜色」，先想清楚它能不能**替使用者把规则守住**；
5. 改完必须跑一遍 `verify-components.mjs`，并把新的结构加进断言的预期里。

## 六、这次踩到的两个新坑（以后会用得上）

1. ⚠️ **`fs.rmSync` 删 Edge 的 profile 目录，被沙箱的"批量删除保护"拦下了**：
   `SAFE_DELETE_BULK_CONFIRM_REQUIRED {"count":651,"threshold":50}`。
   profile 动辄几百个文件，而沙箱一次删超过 50 个文件就要确认。
   → 所有截图/验证脚本改成**每次用带时间戳的新 profile 目录，绝不删旧的**（反正都在 `.tmp` 里）。
2. ⚠️ **审查「间距刻度」时，`margin: auto` 会被算成具体像素**（22.5px / 63.7px / 159.33px），
   看着像"间距不齐"，其实是居中或 flex 里推到最右。**必须先回查样式表确认作者写的是 auto**。
   （Day 9 已在 `audit.mjs` 里处理过，这次新脚本 `verify-components.mjs` 一开始漏了，导致 5 处误报。）
