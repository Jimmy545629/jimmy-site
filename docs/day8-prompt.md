# Day 8 · 一句话需求原文

> 今天的板块①「一句话生成页面」，要求先用**一句话**把主视图要长什么样说清楚，
> 再让 AI 照着这句话去生成（或核对）页面。下面是当天实际使用的那一句。

## 一句话

**把来源看板的主视图做成这样：最上面一条「今天最该看的来源」提示，下面一格一格排着来源卡片（每张卡片显示名称、最近一次记录是几天前、一共记了多少条），再下面是按时间倒序排的记录列表，每条显示标题、属于哪个来源、什么时候记的；没有数据的时候要有空状态提示。**

## 这句话拆成了哪些要求

| 拆出来的要求 | 落在哪个文件 | 对应 PRD 功能 |
| --- | --- | --- |
| 顶部「今天最该看的来源」提示条 | `index.html` 的 `#focus-bar` → `assets/ui.js` 的 `renderFocusBar()` | F2 久未记录提示 |
| 来源卡片：名称 / 最近记录几天前 / 一共多少条 | `assets/ui.js` 的 `sourceCard()` | F1 来源卡片显示项 |
| 记录列表按时间倒序 | `assets/rules.js` 的 `sortItems()` → `renderTimeline()` | F4 时间线 |
| 每条显示标题、属于哪个来源、什么时候记的 | `assets/ui.js` 的 `itemRow()` | F4 时间线 |
| 没有数据时有空状态提示 | `renderSources()` / `renderTimeline()` 的 `empty` 分支 | PRD 页面状态 |

## 核对结果（Day 8 当天）

上面这五条要求，Day 7 做出来的 MVP **已经全部实现**，逐字对得上。

所以 Day 8 没有重写页面，而是：

1. 把页面**真跑起来**（起本地静态服务 + 用 Edge 打开）；
2. 按**方案 A** 往浏览器里手工录入 mock 数据（5 个来源 + 12 条记录），
   **纯模拟真人点击输入，不改产品代码**；
3. 截图存档，证明「列表和卡片用本地假数据渲染」这条完成标准成立。
